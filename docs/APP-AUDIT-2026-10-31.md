# Far Flow audit and improvements — 31 October 2026

Far Flow already has a useful local dictation engine. The main gaps in daily use were window lifetime and the integration of its existing Scratchpad. This pass completes the personal-notes workflow first. Meeting capture remains a separate next increment; personal notes must not imply that calls are being recorded.

## How it works

- `AppModel` is the main-actor coordinator. Fn gestures or buttons start `AudioCapture`; stopping resamples the captured microphone audio for local recognition.
- Parakeet v3 runs through FluidAudio/Core ML. Standard Light cleanup uses local rules; Medium, custom styles and explicit transforms can use Qwen through MLX. REA is a development tool, not a runtime dependency or speech engine.
- The insertion layer snapshots the destination at recording stop, verifies it during insertion, and keeps text available when insertion cannot be verified. Existing insertion and Spotify/media fixes present before this audit were preserved.
- The floating AppKit panel is nonactivating. An optional helper pauses/resumes the current macOS media player. Fn handling, model lifetime and the panel belong to the application, so they should outlive the dashboard window.
- A versioned JSON document inside SQLite stores notes, history, personalization and preferences. Transactions provide atomic replacement. Audio is in memory only; active capture stops at approximately five minutes. There is no meeting capture, system-audio ingestion, speaker diarization or crash-recoverable recording.

## Fixed in this pass

1. Removed the dashboard-close handler that unconditionally called `terminate`. Closing no longer stops shortcuts or model hosts. Command–Q still stops capture, shortcuts, the panel, model engines and the owned helper.
2. Replaced the multiwindow dashboard scene with a single `Window`. Retained a scene-opening action at app scope so reopening does not depend on a notification subscriber in closed content.
3. Made the existing Scratchpad discoverable as **Notes**. New Note works from Command–N, menu bar and recording-bar context menu, and selects the new note even when another was already open.
4. Moved note selection into an optional backward-compatible preference. Bindings resolve note IDs instead of retaining array indices; title and content edits update the timestamp in one mutation. Search covers title and content, with recent edits first.
5. Routed in-app Fn dictation to the selected note and froze its ID at recording start. Switching notes does not redirect the result; deleting its destination surfaces the transcript for recovery. Dictate enables hands-free Fn stopping.
6. Replaced the unconditional “Saved locally” claim with actual save-failure state, a persistent warning, retry and export. Export works even when the database could not open.
7. Made restore validate the input, successfully back up current in-memory data, and then atomically replace the stored document. Failed backup blocks replacement. Restore is blocked while dictation or a transform is active.
8. Distinguished SQLite end-of-data from a read failure. A read failure no longer silently becomes an empty user document that might later overwrite existing data.

No new dependency, service, database schema version, general repository abstraction, rich-text engine or synchronization layer was introduced. Existing Scratchpad data loads unchanged. The single-document SQLite design remains adequate for this personal app; split storage or asynchronous batching only if profiling shows a real typing/save problem with large libraries.

## Next improvements, in order

1. **Meeting recording foundation.** Add a distinct meeting session with explicit start/stop and permission setup. Capture microphone plus selected system audio using [Apple’s ScreenCaptureKit audio capture](https://developer.apple.com/documentation/screencapturekit/capturing-screen-content-in-macos) alongside the existing microphone path. Process bounded audio chunks and checkpoint completed transcripts, rather than extending the in-memory five-minute buffer. Keep recording ownership independent of the dashboard. First acceptance gate: a 60-minute call with both sides captured, no duplicate chunks, bounded memory, and useful recovery after interruption.
2. **Meeting notes and summaries.** Store timed transcript segments and a user-editable note; reuse the existing local writing engine for an explicit summary action. Keep original transcript available. Test long English/Dutch meetings, source-grounded summaries and cancellation. Add speaker identification only if it proves necessary; it requires separate quality validation.
3. **Dictation interruption recovery.** Decide whether recoverable audio is wanted before introducing disk recording, since it changes the current privacy promise. Do not silently retain audio just to match Wispr.
4. **Daily-use compatibility pilot.** Exercise live speech and insertion in the actual editors used, including Chrome/Codex and native fields, plus microphone route changes and sleep/wake. Unit tests and synthetic benchmarks do not establish personal-voice accuracy or end-to-end latency.
5. **Only then consider rich text, tabs or calendars.** These add maintenance and permissions. Plain text, searchable notes and manual meeting capture are the smallest useful starting point.

## Verification

- Native Debug unit suite: **66 tests passed**, including five added tests for notes/restart, destination identity, older preferences and safe restore.
- The initial restore fixture compared subsecond dates with the existing second-resolution ISO-8601 export. Fixed the fixture to use exact timestamps; the passing rerun did not change the export format.
- Results: `build/NotesLifecycleUnitTests-fixed.xcresult`; log: `build/notes-lifecycle-tests-fixed.log`.
- A UI regression case now covers note creation, close/reopen, explicit quit, relaunch and content search. It compiled with the test build; the XCTest UI runner was not executed against the user's live app. Those workflows were checked interactively in an isolated app/data profile instead.
- Interactive checks passed: Command–N selects a new note; body search finds the right note; Command–W retains the app; Command–N reopens it; Command–Q removes the review process; relaunch restores both saved text and the selected note.
- Final Release build and deep/strict signature verification passed. Log: `build/notes-lifecycle-release-final.log`. Installed **0.2.2 (4)** at `/Applications/Far Flow.app`; Settings confirms that version.
- Live installed-app checks passed: microphone and Accessibility remain granted, global shortcut active, Spotify transport ready, and closing the red button leaves the floating bar reporting “Far Flow ready. Microphone off.” The bar's Open Far Flow action reopens the dashboard. Live microphone-to-text accuracy and recording-during-close were not exercised in this session.
- The previous installed version is retained at `build/PreviousReleases/Far Flow-20261031-174752.app`. User data and models were not replaced by the installation.
- The review app initially failed before main with a DYLD framework-signing Team ID mismatch caused by ad-hoc signing the copied test bundle. This generated the Apple crash report supplied during the session. Re-signing the review bundle and frameworks with the same development identity fixed launch. The installed Release uses the build script's consistent signing identity; it launched successfully. No security protection was disabled.
- Settings now reads its displayed version from bundle metadata, removing a hard-coded `0.2.1` label discovered during final verification.
